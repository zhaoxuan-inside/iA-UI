# 第 5 章 端到端关键交互流程(总体)

> **本章导读**:本章把页面级流程串成**跨页面旅程**(对应设计书 §2.3 场景与 §5 工作流),是从"全貌(第 1 章)"到"单页细节(第 6 章)"之间的**总体视角桥梁**:先看整条旅程如何串联各页面,再读第 6 章逐页落地。

## 5.1 场景 A:从 0 到 1 极速孵化(Quick Path / Deep Path)

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户(PM/设计师)
    participant P02 as P-02 项目向导
    participant P07 as P-07 PRD 工作台
    participant P01 as P-09 设计工作台
    participant Agent as 外部智能 Agent
    participant Engine as iA-UI 核心引擎
    participant P26 as P-26 交付中心

    User->>P02: 配置品牌基调与目标技术栈
    P02->>Engine: 初始化项目沙箱,挂载适配器契约与 DTCG 字典
    Engine-->>P01: 载入空白活体画布
    User->>P01: Command Director 输入业务愿景 Prompt
    P01->>Agent: 经 MCP 下发愿景上下文(动态投影)
    Agent->>P07: 推演生成结构化 PRD 与实体拓扑
    P07-->>User: 双分栏 PRD 走查
    User->>P07: 走查并【冻结业务基线】(生成指纹哈希)
    P07->>Agent: 触发全画板并发装配指令
    Agent->>Engine: 并发提交多画板 UI Spec 补丁
    Engine->>Engine: L1 校验 + 盒模型物理计算 + 原子提交
    Engine-->>P01: 渲染多端画板 + 全状态 Mock 绑定
    User->>P01: 走查 / 局部干预(澄清卡 / 直接操控)
    User->>P26: 交付导出(双通道 + Click Wave 视频)
    P26->>Engine: 从冻结快照派生四类产物 + SHA-256 签名
    Engine-->>User: 交付工程包(规格+文字+图片+视频)
```

```
P-02 新建项目
  → P-03 向导(起步方式)
      ├─ 快速单页:收窄向导 → 创建 → §4.1 P-09
      └─ 完整孵化:创建 → §6.2 P-07
P-07 PRD 工作台:输入想法 → Agent 推演结构化 PRD → 人工逐章审阅(章节重生成/补充)→ 冻结业务逻辑
  → §4.1 P-09 生成装配(令牌绑定 → 盒模型装配 → 跨端衍生 → 原型挂载 → 全状态 Mock)
  → 引擎确定性执行:校验补丁 / 冲突检测 / 原子提交 → 画布更新 + S-04 会话记录
  → 设计师走查(§4.3 P-11 预览 / Mock 场景切换 / §4.2 P-10 澄清局部干预)
  → §6.7 P-25 验证(四层门禁)→ 自愈 / 人工接管
  → §6.6 P-21 打快照 → §6.6 P-23 提交评审 → 批准 → 发布(冻结)
  → §6.7 P-26 交付(规格 + 文字 + 图片 + 视频)→ 通知研发
关键分支:
  - 中途发现 PRD 需求变更 → 解冻 → P-07 修改 → 画布黄色预警"是否更新 UI?" → 选"更新"重新装配受影响页
  - 单页生成超时(>20s)→ 自动中断回滚 → 提示精简需求重试
  - 交付完整度缺视频 → P-26 标红 → P-11 录屏补齐 → 重新交付
```

## 5.2 场景 B:人机双向精细调优(设计书 §2.3 场景 B / §5.2)

```mermaid
sequenceDiagram
    autonumber
    actor Designer as 设计师
    participant P01 as P-09 画布/控制台
    participant Guard as Scope Guard 引擎
    participant Agent as 外部协作 Agent
    participant CAS as CAS 事务流水线
    participant Canvas as 渲染主画布

    Designer->>P01: 框选局部卡片容器,开启作用域锁定
    Guard->>Canvas: 选区外画板施加只读遮罩 + 锁孔标记
    Designer->>P01: 输入微调意图("让弹窗更有质感")
    P01->>P01: 检测模糊意图 → 弹出澄清卡(2~3 方案)
    Designer->>P01: 点选方案 → 下发确定性意图
    P01->>Agent: 仅下发选区内的局部上下文投影
    par 人机双轨并行
        Designer->>Canvas: 直接拖拽间距(12px→16px)
        Canvas-->>Designer: 标尺实时渲染,松手吸附 spacing.4,弹广播胶囊
    and Agent 异步生成
        Agent->>CAS: 提交补丁(携带 baseVersion)
    end
    CAS->>CAS: CAS 版本检查 + Scope 越界校验
    CAS->>CAS: 冲突字段 → 人工优先(保留人工 16px)
    CAS->>CAS: 非冲突字段无损合并
    CAS->>Canvas: 原子提交并刷新局部视图
    Canvas-->>Designer: 局部微调呈现,选区外零意外漂移
```

```
§4.1 P-09 画布:框选局部 → Cmd+Alt+L 锁定作用域(选区外磨砂 + 锁孔)
  → S-03 意图输入"让弹窗更有质感" → 检测模糊 → §4.2 P-10 澄清卡(2~3 方案)→ 点选
  → Agent 生成候选(引擎校验,越界写被 ScopeViolationException 拦截)→ 画布原子更新
  → 设计师直接拖拽微调:间距吸附 Token → 底部胶囊"是否一键广播全局?" → 选"应用全局/仅本次/忽略"
  → 确定性参数直达:输入"间距 16px" → 硬约束直接生效
  → 与 Agent 异步并发:人工改动与 Agent 补丁冲突 → 人工优先 + 差异合并面板 → 裁决
  → §6.6 P-21 对比版本 → §6.6 P-22 Diff 审阅 → 采纳/回退
  → 更新规格并通知研发(§6.7 P-26 增量交付)
关键分支:
  - Agent 补丁版本过期(baseSnapshotVersion 不符)→ 强制三方合并预览
  - 主组件修改 → 影响清单(全局同步/仅本次/拒绝并保留分叉)
```

## 5.3 场景 C:存量设计导入重构(设计书 §3.3 路径 B)

```mermaid
sequenceDiagram
    autonumber
    actor Designer as 设计师
    participant P01 as P-09 画布
    participant P20 as P-20 转换报告
    participant Importer as 逆向清洗引擎
    participant Canvas as 活体语义画布

    Designer->>P01: 拖拽导入存量 .fig / 截图
    P01->>Importer: 启动解析器读取图元树
    Importer->>Importer: 写入 L1 原始图元只读备份
    Importer->>Importer: 逆向推导 Auto-Layout + 聚类对齐 DTCG Token
    Importer->>P20: 生成三级保真度损失报告与降级清单
    P20-->>Designer: 弹出报告抽屉(统计卡 + 降级/丢失清单)
    Designer->>P20: 点击降级项行号 → 画布定位并高亮问题图元
    Designer->>P20: 确认降级方案 → 载入活体语义画布
    P20->>Canvas: 挂载流式盒模型树 + 受控自由画布
    Canvas-->>Designer: 可无损直接操控的活体设计
```

```
P-02 导入设计 / P-03 导入起步
  → §6.5 P-19 导入向导:选择文件 → 配置保真等级(L1/L2/L3)与目标技术栈 → 解析
  → §6.5 P-20 转换报告:统计卡(容器转换率/Token 归一化率/降级/丢失)→ 分栏清单 → 定位节点
  → 进入 §4.1 P-09:逐项审阅降级 / 丢失项 → 修正
  → 语义重构:绝对坐标 → 流式盒模型;散乱色值 → Token(裸色值扫描 + 对齐)
  → 组件映射:识别组件绑定注册表;缺失组件进入"待沉淀"列表
  → §6.7 P-25 验证:L2 视觉比对(与原图差异)→ 优化 → 通过
  → 交付(§6.7 P-26)
关键分支:
  - 解析严重损坏 → "回退至原始绝对布局草稿"保底
  - 无法识别的内联样式 → "待清洗样式池" + 一键对齐建议
```

## 5.4 场景 D:验证与交付自愈闭环(设计书 §5.3)

```mermaid
sequenceDiagram
    autonumber
    actor Engineer as 研发工程师 / CI
    participant P25 as P-25 验收控制台
    participant Validator as 四层验收引擎
    participant Agent as 编码自愈 Agent
    participant Human as 人工升级接管面板

    Engineer->>P25: 触发四层量化验收流水线
    loop 自愈循环(最多 3 轮)
        Validator->>Validator: L1 规格合法性(100% 门禁)
        Validator->>Validator: L2 视觉与布局(≥98% 门槛)
        Validator->>Validator: L3 交互与业务(100% 用例)
        Validator->>Validator: L4 工程可交付(PASS)
        alt 四层全部达标
            Validator-->>P25: 验收通过,打发布快照标签
        else 发现缺陷且轮次 ≤3
            Validator->>P25: 生成结构化诊断单(组件ID/行号/规则)
            P25->>Agent: 下发诊断单 + 回归测试集
            Agent->>Validator: 提交自愈修正补丁
        end
    end
    alt 超过 3 轮仍未通过
        Validator->>Human: 触发自愈熔断(ERR_HEALING_CIRCUIT_BREAK)
        Human-->>Engineer: 弹出人工升级接管抽屉
        Engineer->>Human: 人工确认调整或微调容差门槛
        Human->>P25: 手动放行并归档审计
    end
```

```
研发实现(基于 UI Spec 生成代码)
  → 受控浏览器渲染(Playwright)→ 视觉 / 规范比对
  → §6.7 P-25 结构化诊断:布局溢出 / 裸色值 / 状态缺失 / 文字截断 / 对比度 / 悬空路由
  → 外部 Agent 依据诊断自愈(≤3 轮,携带回归测试)
      ├─ 通过 → 交付 / 更新规格
      └─ 未达标 → 人工升级接管
  → 研发提交验证回执 → P-25 汇总(实现偏差定位)
```

## 5.5 场景 E:并发冲突处理(设计书 附录 A.4)

```mermaid
sequenceDiagram
    autonumber
    actor Human as 设计师
    actor Agent as 外部 Agent
    participant CAS as CAS 事务流水线
    participant Engine as iA-UI 引擎

    par 并发编辑同一项目
        Human->>CAS: 人工修改(尺寸 / 间距)
    and Agent
        Agent->>CAS: 异步提交补丁(携带 baseSnapshotVersion)
    end
    CAS->>CAS: 版本号比对(CAS)
    alt 版本过期
        CAS->>CAS: 强制三方合并预览
    else 版本有效
        CAS->>CAS: 权限 / 引用 / 作用域边界校验
        alt 越界
            CAS-->>Agent: REJECTED(ScopeViolationException)
        else 校验通过
            CAS->>CAS: 影子沙箱试运行 + 规则校验
            CAS->>CAS: 原子提交或整体拒绝
        end
    end
    alt 存在冲突字段
        CAS->>CAS: 人工优先原则 + 差异合并面板
        Human->>CAS: 显式裁决(采纳 / 拒绝)
    else 非冲突字段
        CAS->>CAS: 自动无损合并
    end
    Note over CAS: 每次提交记录:变更原因 / 差异 / 验证结果 / 可回滚版本
```

```
人工与外部 Agent 并发编辑同一项目
  → 版本号比对(CAS)
      ├─ 基于最新版本 → 补丁校验(权限/引用/作用域边界)→ 原子提交
      └─ 版本过期 → 强制三方合并
  → 冲突检测:
      ├─ 非冲突字段(人工改尺寸,Agent 改文案)→ 自动无损合并
      └─ 冲突字段(同属性)→ 人工优先 + 差异合并面板 → 显式裁决
  → 提交:临时版本应用 → 规格与依赖验证 → 原子提交或整体拒绝
  → 每次提交记录:变更原因 / 差异 / 验证结果 / 可回滚版本
```
