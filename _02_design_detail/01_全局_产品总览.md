# 第 1 章 产品总览(总体)

> **本章导读**:先看全貌,不进入任何细节。读完本章,你应该能回答三个问题:① 这个产品解决什么问题(§1.2);② 产品由哪些能力域、哪些页面组成(§1.4 / §1.5);③ 设计遵循哪些总原则(§1.3)。后续所有章节都是本章的展开。

## 1.1 文档目的与范围

本说明书把产品设计书中的**能力描述**翻译为**可实施的设计规格**:

- **页面级详细设计**:每一个界面(页面 / 浮层 / 面板)的定位、布局结构、区域组成、关键组件、可见状态(加载 / 空 / 错误 / 权限不足);
- **交互流程说明**:每个功能 / 页面的触发入口、用户操作路径、系统响应、分支条件、异常与恢复路径;
- **状态机与规则汇总**:生成、补丁、版本、Agent 连接等生命周期状态的流转与 UI 呈现;
- **端到端旅程**:跨页面的关键用户旅程(从 0 到 1、人机精调、导入重构、验证自愈、并发冲突)。

范围边界(与设计书一致):

- 只设计**产品自身 UI 与交互**,不设计外部 Agent 内部逻辑;外部 Agent 在本说明书内表现为"外部协作方,通过 MCP 调起产品能力并在产品 UI 中以会话 / 任务形式呈现"。

- 平台 UI 自身的令牌 / 无障碍 / 多语言规范与设计书 §3.2、§7 一致。

## 1.2 产品定位与能力全景

> 一句话定位:iA-UI 是一个 **AI 原生语义设计平台** —— 人类直接操控与外部 Agent(经 MCP)共用同一份**语义文档树**与 **UI 操作设计语言(UIOL)**,以"指令流 ⇄ 文档树"为单一事实来源,覆盖 **需求(PRD)→ 设计生成 → 人机协同精调 → 沉淀(组件/令牌/资产)→ 配置(原型/Mock/多终端)→ 导入 → 治理(版本/发布/团队)→ 验证 → 交付** 的全链路。

**能力全景表**(9 大能力域 × 覆盖页面 × 一句话能力):

| 能力域 | 覆盖页面 | 一句话能力 |
|---|---|---|
| 入口与项目管理 | P-01 ~ P-06 | 认证、项目创建与管理、项目设置、外部 Agent(MCP)连接管理 |
| 需求与 PRD | P-07 ~ P-08 | 宏观深思的结构化 PRD 工作台与需求全链路追踪 |
| 设计工作台(核心) | P-09 ~ P-11 | 三支柱设计工作台、模糊意图澄清、可操作预览 |
| 沉淀域 | P-12 ~ P-15 | 组件库 / DTCG 令牌 / 组件逆向注册 / 设计资产 |
| 配置域 | P-16 ~ P-18 | 交互原型编辑器、全状态 Mock、多终端管理 |
| 输入域 | P-19 ~ P-20 | 存量设计导入与保真度转换报告 |
| 治理域 | P-21 ~ P-24 | 版本快照 / Diff / 生命周期发布 / 团队管理 |
| 验证与交付域 | P-25 ~ P-26 | 四层量化验证与双通道(机器 + 人类)交付 |
| 平台管理域 | P-27 | 组织 / 成员 / 凭证 / 计费 / 审计 |

**两条主线(理解产品的钥匙)**:

1. **单一事实来源(语义文档树)**:画布、结构树、属性面板、预览、交付物都是同一棵语义文档树的**投影**,任何视图改动即时同步其余视图 —— 详见 §2.1;
2. **交互中枢(UIOL)**:人类手势与外部 Agent 指令都收敛为同一套**语义指令流**,经事务引擎原子写入文档树,可审计、可回滚、可并发合并 —— 详见 §2.2。

**核心页面**:设计工作台 P-09 是产品中枢,承载三支柱布局(意图中枢 + 语义画布 + 约束控制台)与全部生成 / 编辑 / 协同体验 —— 详见第 4 章。

## 1.3 总体设计原则

1. **单一事实来源**:画布、结构面板、属性面板、Agent 会话、交付物均消费同一份语义文档树(设计书 §3.3);任意视图改动即时同步其余视图。→ 落实为 §2.1 / §2.3。
2. **三支柱布局**:意图中枢(左)→ 语义画布(中)→ 约束控制台(右),贯穿工作台(设计书 §4.4)。→ 落实为 §4.1。
3. **确定性反馈优先**:一切修改经"校验 → 预览 → 确认(必要时)→ 原子提交"路径,禁止静默写入(设计书 附录 A.4)。→ 落实为 §2.3 事务引擎、§3.3 反馈组件。
4. **人类优先**:人工操作与 Agent 并发时人工胜出;模糊意图必须主动澄清(2~3 方案),不猜(设计书 §4.5)。→ 落实为 §4.2、§5.5。
5. **双通道可交付**:任何设计状态都可一键产出 UI Spec + 文字 + 图片 + 视频,四要素齐备才允许"交付"(设计书 §6)。→ 落实为 §6.7 P-26。
6. **作用域即 UI**:锁定、传播、全局影响在界面上以遮罩 / 光效 / 警示胶囊显式呈现,避免"改了哪不知道"。→ 落实为 §3.4、§4.1。

